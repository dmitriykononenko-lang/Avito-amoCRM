# CLAUDE.md — контекст проекта для Claude Code

Проект ko:agency (Дмитрий Кононенко). Интеграция Avito ↔ amoCRM как собственный тиражируемый продукт (виджет). Отвечай на русском.

## Цель v1
Клиент пишет на Avito → сообщение в чате amoCRM, привязано к нужному контакту и сделке → менеджер отвечает из amoCRM. Звонки Avito с подменных номеров → звонок с записью в карточке. Полное ТЗ: `docs/TZ.md`, план: `docs/PLAN.md`.

## Принятые решения (не менять без согласования с Дмитрием)
- Мультиаккаунт: много клиентов (tenant = аккаунт amoCRM), у каждого несколько аккаунтов Avito (компании).
- Переписка — через amoCRM **Chat API** (свой канал, регистрирует техподдержка amoCRM), не через примечания.
- Сделка: есть открытая по тому же объявлению → пишем в неё; все закрыты или другое объявление → новая у того же контакта (`src/domain/rules.ts`).
- Контакт: ключ — Avito user_id покупателя; телефон — из звонка или вручную (из текста — v2).
- Воронка/этап/ответственный — из настроек по аккаунту Avito; ответственный переопределяется по объявлению.
- Файлы (не фото) в Avito API не отправляются → ссылка с TTL или ошибка доставки (настройка).
- Своя IP-телефония — НЕ делаем. Звонки обычной телефонии пишет виджет провайдера; мы обеспечиваем склейку по телефону.
- Хостинг: VPS ko:agency в РФ, docker compose, PostgreSQL. Без Redis/Kafka/n8n.
- UTM: utm_source=avito, utm_medium=chat|call, utm_campaign=avito user_id продавца, utm_content=item_id.

## Жёсткие правила
- Секреты и ПДн никогда не логируем и не коммитим. Токены в БД — только через `SecretBox`.
- Каждый обработчик задачи идемпотентен. msgid в amojo = ID сообщения Avito.
- Хук amojo приходит ОДИН раз и не повторяется: только проверка подписи + inbox + 200, логика — в воркере.
- amoCRM: ≤ 6 rps на аккаунт (лимит 7), иначе 429 → блок 403.
- Методы Avito в `src/avito/client.ts` помечены `VERIFY` — сверены по неофициальному SDK, т.к. developers.avito.ru не открывался при проектировании. Перед использованием метода сверить со swagger на https://www.avito.ru/developers/api-catalog и снять пометку.
- Не выдумывать методы и поля API. Нет в документации → открытый вопрос в `docs/PLAN.md`.
- Денежные условия, цены, договорные условия — только через Дмитрия.

## Команды

## Виджет
